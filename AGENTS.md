# AGENTS.md

## What this repo is
- HAXcms micro-site. Root `index.html`, `site.json`, `pages/*/index.html`, `files/`, `theme/` are deployed site content.
- Active theme is `custom-haxquiz-theme` (see `site.json` → `metadata.theme`), a custom element shipped via the custom bundle.
- `custom/` is a Rollup-built HAX custom bundle. Entry `custom/src/custom.js` → `custom/build/custom.es6.js` (tracked in git via `!custom/build` in `.gitignore`).
- `src/` is a leftover React/Vite shell not wired into any root script.

## High-signal commands
- Root dev server: `npm run serve` → `npx @haxtheweb/haxcms-nodejs`
- Root dev mode: `npm run dev` (POSIX `NODE_ENV=development` syntax; on Windows cmd use `npm run serve` instead)
- GitHub Pages prep: `npm run ghpages:build`
- GitHub Pages deploy: `npm run ghpages:deploy` (build, then push repo root to `gh-pages` branch)
- Custom bundle watch: `cd custom && npm run watch`
- Custom bundle build: `cd custom && npm run build`
- Custom manifest scan: `cd custom && npm run analyze`

## Repo quirks
- No lint/test/typecheck scripts at root or in `custom/`; do not invent them.
- `scripts/ghpages-build.js` is destructive and order-sensitive: deletes `index.html`, renames `ghpages.html` → `index.html`, removes `build/` + `wc-registry.json` + `assets/babel*`, and exits 1 if `ghpages.html` is missing. `ghpages.html` is NOT currently in the repo — `ghpages - Copy.html` / `index copy.html` / `index-deploy.html` are manual backups the script does not use.
- `custom/build/custom.es6.js` is generated but committed intentionally; never edit it directly, rebuild from `custom/src/`.
- `custom/src/quiz-dashboard-lite2/` is a nested, self-contained element package (own `package.json`, `node_modules`, demos, tests, `steering/` docs) vendored under `custom/src`; `custom.js` imports it alongside `custom-haxquiz-theme.js`, `notif-element.js`, `todo-list.js`.
- `vite.config.ts` exists but root scripts do not use it.
- `web-dev-server.haxcms.config.cjs` is local HAXCMS dev config; keep `https: true` and `open: true` unless changing dev flow.
- `graphify-out/` dirs (root, untracked; inside `quiz-dashboard-lite2`, committed) are generated by the graphify skill; don't edit them.
- Root has stray legacy files (`.dddignore`, `false`, `*.xsd`, `config.php`, `index copy.html`, etc.); leave them untouched.

## Editing rules
- Prefer semantic HTML in `pages/*/index.html`; update `site.json` items when page structure changes.
- Theme/elements: edit source in `custom/src/`, then `cd custom && npm run build`.
- Do not edit generated build artifacts unless the task explicitly targets build output.
- Preserve existing HAXcms theme/custom bundle wiring (`build.js`, `build-haxcms.js`, `theme/`, root configs); many files are legacy fallback code, so change only targeted lines.

## Existing instruction sources
